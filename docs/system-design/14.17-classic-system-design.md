## 1. Design This Project at 100x Scale (7,500 RPS)

### Requirements & Estimation
- **Functional**: Sub-50ms statutory standard identification and gap analysis for 10 million audits/month; 7,500 peak queries/sec.
- **Non-Functional**: 99.99% availability, zero cloud token costs, strict data privacy.
- **Compute Sizing**: 7,500 RPS $\times$ 14ms compute $= 105$ dedicated CPU cores. Distributed across 16 Kubernetes nodes (8 cores each).

### Architecture Diagram
```mermaid
flowchart TD
    Client["Client Browsers / Factory Gateways"] --> CDN["Cloudflare CDN (DDoS & TLS 1.3)"]
    CDN --> ALB["AWS Application Load Balancer (Least Connections)"]
    
    subgraph K8s["Kubernetes Cluster (16 Stateless Pods)"]
        Pod1["Pod 1: FastAPI + Local FAISS"]
        Pod2["Pod 2: FastAPI + Local FAISS"]
        PodN["Pod N: FastAPI + Local FAISS"]
    end
    
    ALB --> Pod1
    ALB --> Pod2
    ALB --> PodN
    
    subgraph DataCache["Data & Shared Cache Tier"]
        RedisCluster["Redis Cluster (Query Embedding Cache)"]
        S3["AWS S3 / MinIO (Central Master Index Artifacts)"]
    end
    
    Pod1 <--> RedisCluster
    Pod2 <--> RedisCluster
    PodN <--> RedisCluster
    Pod1 -.->|Boot Preload| S3
```

### Deep Dive & Bottlenecks
- **Embedding Cache**: 70% of factory queries target the top 500 mandatory standards (cement, steel, cables). Redis cluster caches the 384-dimensional float arrays for these queries, eliminating ONNX computation for 5,250 of the 7,500 RPS.
- **Index Distribution**: Master FAISS index updates are published to S3; pods poll S3 or receive an event hook to atomically reload memory pointers without downtime.

## 2. Design the Regulatory Gazette Notification System

### Requirements & Estimation
- **Functional**: Notify compliance officers via Email, SMS, and WhatsApp when new Quality Control Orders (QCOs) or gazette amendments are published.
- **Volume**: 500,000 subscribed manufacturers across India; 5-10 gazettes published monthly.

### Architecture Diagram
```mermaid
flowchart LR
    Crawler["Government Gazette Crawler (crawl_standards.py)"] --> Ingest["Ingestion Validator"]
    Ingest --> DB[(Gazette Database)]
    Ingest --> Kafka["Kafka Topic: 'qco-published'"]
    
    Kafka --> Group["Consumer Group: Notification Engine"]
    Group --> Fanout["Fanout Worker (Partitioned by Ministry/HS Code)"]
    Fanout --> Queue["Celery Priority Queue"]
    
    Queue --> WorkerSMS["SMS Service (NIC / CDAC Gateway)"]
    Queue --> WorkerEmail["Email Worker (AWS SES / SendGrid)"]
    Queue --> WorkerPush["Browser WebPush Worker"]
```

### Deep Dive
- **Fanout & Deduplication**: To avoid spamming, the fanout worker queries subscribed product categories (e.g., users registered for "Civil Engineering & Cement") and enqueues notification payloads with idempotency keys (`gazette_id:user_id`).

## 3. Design the Semantic Search System (20,000 Standards)

### Requirements & Estimation
- **Functional**: Search over 20,000 national standards with typo tolerance, synonym resolution, and sub-10ms response times.
- **Storage**: 20,000 records $\approx 30$ MB FAISS index; 25 MB inverted BM25 text index.

### Architecture Diagram
```mermaid
flowchart TD
    UserQuery["User Query"] --> Analyzer["Query Pre-processor (Regex standard codes)"]
    Analyzer --> Split{"Direct Standard Code?"}
    Split -->|Yes: e.g. '12269'| Direct["Exact Inverted Index Lookup (<1ms)"]
    Split -->|No: Descriptive| Hybrid["Hybrid Search Pipeline"]
    
    Hybrid --> Dense["FastEmbed Dense Vector (384d) -> FAISS IndexFlatIP"]
    Hybrid --> Sparse["BM25 Inverted Term Index (RankBM25)"]
    
    Dense --> RRF["Reciprocal Rank Fusion (RRF Scoring)"]
    Sparse --> RRF
    
    RRF --> Top20["Top-20 Candidate Standards"]
    Top20 --> CrossEncoder["Lightweight Cross-Encoder Reranker"]
    CrossEncoder --> Top3["Top-3 Calibrated Results with Confidence %"]
```

## 4. Design the Factory Certificate & Document Upload System

### Requirements & Estimation
- **Functional**: Secure upload of 25MB NABL calibration and factory layout PDFs; automatic OCR verification.
- **Security**: Antivirus scanning, cryptographic HMAC signing, presigned URLs.

### Architecture Diagram
```mermaid
sequenceDiagram
    autonumber
    actor Officer as Compliance Officer
    participant FE as React Frontend
    participant API as FastAPI Backend
    participant S3 as Private Object Storage (S3 / MinIO)
    participant Worker as Background OCR Worker (Celery)

    Officer->>FE: Selects calibration certificate PDF (15MB)
    FE->>API: POST /documents/upload-url {filename, hash}
    API->>API: Generate Presigned S3 PUT URL (TTL: 5 mins)
    API-->>FE: Presigned Upload URL
    FE->>S3: Direct PUT binary upload (Bypasses API server)
    S3-->>API: S3 Event Notification (ObjectCreated)
    API->>Worker: Enqueue OCR Verification Task
    Worker->>S3: Read PDF & execute Tesseract OCR
    Worker->>Worker: Parse NABL accreditation number & expiry date
    Worker->>API: Update document verification status
```

## 5. Design a Rate Limiter for Regulatory AI Queries

### Requirements & Estimation
- **Functional**: Enforce sliding window limits (30 req/min per IP; 500 req/min per enterprise API key).
- **Scale**: Sub-millisecond evaluation across 10,000 concurrent IPs.

### Architecture Diagram
```mermaid
flowchart LR
    Req["Incoming HTTP Request"] --> Nginx["API Gateway / Proxy"]
    Nginx --> Middleware["FastAPI Rate Limit Middleware"]
    Middleware --> Redis["Redis Cluster (Sliding Window Counter via Lua Script)"]
    
    Redis --> Check{"Current Count < Limit?"}
    Check -->|Yes| Allow["Increment Counter & Proceed to /chat"]
    Check -->|No| Block["Return 429 Too Many Requests (Retry-After)"]
```
